The problem

Scraping prices is hostile work
for a business on 12% margins

01

Margin is one cent wide

Price $2 above a competitor and conversion collapses. Price too low and every order fulfils at a loss. Dropshippers reprice constantly, by hand or not at all.

02

The web fights back

Anti-bot blocks, JavaScript memory bombs, redirect chains, and deceptive $0.00 microdata written specifically to mislead repricing bots.

03

The blast radius is the store

A scraper that shares an IP or network with the storefront risks taking the storefront down with it. One bad page should never touch production.

So the interesting engineering is not the scraping. It is containing it.

The product

A centralized control layer.
Never a scraper on your own machine.

  • Goal in — a product and a margin target, in plain language.
  • Orchestrator plans — the goal decomposes into per-retailer capture tasks.
  • Sandboxes execute — headless Chromium in a disposable container, one per store, in parallel.
  • Screenshots return — evidence lands in the shared workspace, byte for byte.
  • Vision verifies — a vision model audits the rendered page, not the DOM, so injected text cannot lie to it.
  • Hard purge — the container is destroyed. Nothing survives the task.

Parallel by default

Every retailer is a separate container, captured concurrently. One slow or hostile site cannot stall the others.

Evidence, not assertions

Each quote carries a screenshot artifact and a provenance label — live or synthetic — so nothing unverified is presented as fact.

Human gate before money

Anomalous prices freeze for operator review. Repricing is an approval decision, never an autonomous purchase.

Architecture

One control plane, many disposable workers

CONTROL PLANE · VULTR CLOUD COMPUTE

FastAPI orchestrator

Task planning, container lifecycle, WebSocket telemetry, human-in-the-loop state.

  • Pre-warmed pool — no cold start mid-demo
  • 60s hard watchdog per task
  • Two-tier verifier
WORKER PLANE · EPHEMERAL CONTAINERS

Hardened Playwright sandbox

Chromium under a non-root user, writable only to its own task directory.

  • 1.0 vCPU · 512 MB · swap disabled
  • --cap-drop=ALL, no-new-privileges
  • Egress blocklist on link-local + RFC1918
INTELLIGENCE PLANE

Vultr Serverless Inference

Vision pass over the rendered screenshot. Reads what a user would see, which is what defeats text-level prompt injection in hidden DOM nodes.

INTERFACE

Operator dashboard

WebSocket log stream, live sandbox viewport, price band with provenance, and explicit approve / purge controls.

Containment

Four pillars, each independently enforced

PillarMechanismObservable proof
Process isolation Separate container per task. Non-root worker user. --cap-drop=ALL and no-new-privileges so privilege escalation has no path. Browser PID namespace cannot see the host or other tasks.
Secret hygiene Sandbox receives a task ID and a target URL. Nothing else. API keys exist only in the orchestrator process. env inside the sandbox contains no credentials.
Resource limits 1.0 vCPU, 512 MB memory, swap pinned equal to the memory cap so it cannot spill, 60s watchdog. Runaway page dies at the ceiling; host stays responsive.
Lifecycle discipline Ephemeral workers purged with docker rm -f on completion, failure, or rejection — including on timeout. State reaches WIPED_AND_PURGED; pool rotates fresh containers.

Scope note. The deployed host runs the standard Docker runtime. gVisor (runsc) is supported as a drop-in runtime and is selected when present, but it is not installed on the current VM, so containment here rests on namespaces, cgroups, and the controls above — not on syscall interception.

The containment moment

What happens when a retail page attacks the host

# hostile page, evaluated inside the sandbox fetch("http://169.254.169.254/latest/meta-data/") .then(r => r.text()) .then(d => exfiltrate(d)); # result, observed live connect() → ECONNREFUSED / timeout no credentials present to steal no route to link-local or RFC1918 container purged after the task
  • The attempt is real. The page genuinely issues the request — it is not simulated.
  • The request dies at the boundary. Link-local and RFC1918 egress is dropped by container and host rules.
  • There is nothing to steal. No key, token, or credential is ever mounted into a sandbox.
  • Nothing persists. The container is removed; its filesystem goes with it.

Containment is demonstrated, not asserted: the same request that would succeed on an unprotected host fails visibly inside Ghost Shopper.

Cost of the alternative

A blocked scraper IP can take a storefront's own traffic with it. The risk is not the price of compute — it is a revenue outage during peak season, or a leak of cloud credentials from a malicious page.

Where the money is made

Repricing against a verified median, with an honest band rather than a point estimate, and a human approving every move. That is the difference between a scraper and a pricing system a merchant will actually let run.

Status · stated plainly

What works, and what we would fix next

Working

  • Orchestrator deployed on Vultr Cloud Compute, publicly reachable
  • Sandbox lifecycle: create, execute, purge
  • Egress blocklist against metadata and private ranges
  • Resource caps and watchdog enforcement
  • Vision-verified capture path and human approval gate

Known gaps

  • Price generation falls back to a heuristic when inference fails — the number is plausible, not observed
  • Real prices scraped by the worker are not yet wired through the API response
  • gVisor not installed on the current host; standard runtime in use

We would rather show this than hide it. Containment is the claim under test, and containment is real. Pricing accuracy is the next milestone.
